# Detailed employee payslips

The branded A4 PDF starts with employee details, period, worked/leave counts, saved earnings and deductions, take-home pay and the rates used for normal salary, overtime and late deductions. Employee EPF basis/rate and employer EPF/ETF remain distinct. A complete calendar-day breakdown follows, with attendance state, saved check-in/out, normal pay after short-day reductions, OT hours/rates/pay, raw/charged late hours and amount, named dated adjustments and the resulting day subtotal. Named recurring components and salary advance recoveries are itemised separately.

The day subtotal excludes period EPF, salary advance recovery and undated components; it is not daily take-home pay. Recurring items are never spread across arbitrary dates. Claim-backed components use their saved calculation date/reason. Repeated rates are grouped by type/rate, so a policy change in the pay period does not make all OT appear to use a single rate. Late hours before grace and charged hours are labelled separately. Paid leave earns its configured daily amount; unpaid leave and recorded absence do not. Sunday work stays in the ledger.

New runs and explicit draft regeneration save source attendance and employee identity/department/designation/join date in calculation detail. Viewing a payslip does not fetch current punches or recalculate earnings. Older snapshots show only available saved calculation entries; missing days/rates/punches are marked unavailable. Older identity uses current profile fields with an explanatory note. Any saved salary/OT/late totals that cannot be allocated to available day entries are disclosed; saved summary values are authoritative.

The existing document endpoint and print/PDF security remain unchanged. Repeating table headers, page numbers, confidential reference footers and row pagination are included. The sample preview uses clearly labelled fictional employee data and actual calculation functions. The workbook salary export retains its existing layout. No new database migration is required; attendance and identity are stored in the existing JSON calculation snapshot.
