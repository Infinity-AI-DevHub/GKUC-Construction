# Client approval evidence and certified payment requests

Open a Certified progress claim to upload the final client-approved measurement/certificate document under Client-approved certificate / final approval proof. Multiple files retain supporting revisions; title/category, original filename, uploader and time appear in the attachment list. The main register shows the approved-proof count. Uploads use the existing protected attachment/storage path and do not parse or change certified amounts. They are optional and available after recording certification; the generated Certificate PDF remains a separate system record. The proof upload requires finance.invoice and readers match the progress claim read permissions. The proof section does not expose a delete action.

Certified claims now have Payment request PDF, Print payment request and Edit payment letter actions. The separate letter uses the recorded certificate reference/date, valuation period, certified net payable, actual receipts, current outstanding balance and due date. It does not request the original submitted value. Recipient/address, letter date, subject and wording can be saved independently of the application covering letter or certification amounts. The payment request signatory is always the authenticated printing/downloading user: name and current role name are read from users/roles at document generation, including signed PDF ticket requests. Saved or submitted manual signatory fields cannot override this identity. Application covering-letter signatories remain separate. A fully settled certificate shows no outstanding balance. Printing does not send the letter or record a receipt. Existing application covering letters remain available.

The startup migration extends attachment owner types with progress_certificate and adds the JSON progress_claims.payment_request_details field. Storage folder permissions must support the configured generic upload path. New PDF ticket canonicalisation includes payment-request, while preserving query-bound signed ticket checks. Current receipts are read when printing; the letter does not create another invoice or receivable.

Verification covers pre-certification upload/letter rejection, final proof upload/list/open permissions, proof counts, partial-payment arithmetic, saved letter details and actual PDF ticket rendering. Browser verification exercises proof selection/upload/listing and letter editing; a rendered one-page sample letter was visually reviewed.
